# Local Translator

Локальный переводчик книг в PDF. Работает целиком на вашем компьютере через [Ollama](https://ollama.com):
текст не уходит в облако. На выходе получается новый PDF с переводом, в котором сохранены абзацы,
иллюстрации и размер страниц оригинала.

По умолчанию книга переводится с английского на русский моделями `translategemma`. Языки и модели меняются в `config.yaml`.

## Возможности

- **Два прохода.** Быстрая модель переводит всю книгу, а куски с подозрительным результатом
  переделывает более крупная. Есть три режима: «Быстрый», «Сбалансированный» и «Качественный».
- **Проверки качества.** Перевод проверяется по длине, по доле латиницы, по повторам (признак
  зацикливания модели), по терминам глоссария, по числам и единицам измерения, по согласованию
  рода персонажей. Куски, не прошедшие проверку, видны в интерфейсе.
- **Глоссарий и подсказки.** Обязательные термины (`glossary.tsv`) модель должна использовать, проверка
  это требует. Подсказки (`hints.tsv`) модель только видит. Глоссарий можно импортировать из `.xlsx`.
- **Персонажи.** Программа находит имена и предлагает указать пол персонажа, чтобы в русском тексте
  совпадали окончания глаголов и прилагательных.
- **Группы книг.** У серии книг общий глоссарий и общий список персонажей (`context/<группа>/`).
- **Возобновление.** Состояние хранится в SQLite (`state.db`). Прерванный перевод продолжается с
  того же места. Если поменять промпт или модель, переведутся заново только затронутые куски.
- **Интерфейс.** Очередь книг, параллельное чтение оригинала и перевода, правка глоссария,
  журнал работы в реальном времени.

## Как это устроено

```
PDF ─► extract ─► chunk ─► LLM, проход 1 ─► validate ─► LLM, проход 2 ─► render ─► PDF
       (PyMuPDF)          (Ollama, 4B)                  (Ollama, 12B)    (Jinja2 + Chromium)
```

| Часть | Технологии | Папка |
|---|---|---|
| Конвейер перевода, CLI | Python 3.11+, PyMuPDF, Playwright, Jinja2 | `src/` |
| Сервер интерфейса | Go, SQLite (`modernc.org/sqlite`) | `backend/` |
| Интерфейс | React 19, TypeScript, Vite | `frontend/` |

Сервер на Go отдаёт интерфейс, встроенный в исполняемый файл, и запускает конвейер командой
`python -m src.cli …`. Python он ищет в `.venv` проекта, а если там его нет, берёт системный.
Сервер слушает только `127.0.0.1` и отклоняет изменяющие запросы с чужим `Origin`.

## Требования

- [Ollama](https://ollama.com) и модели:
  ```sh
  ollama pull translategemma:4b
  ollama pull translategemma:12b
  ```
  Для 12B желательна видеокарта примерно с 10 ГБ памяти. Без неё модель частично работает на CPU и сильно медленнее.
- Python 3.11+
- Go 1.26+ и Node.js 20+ (только для сборки интерфейса)

## Установка

```sh
git clone <url> local-translator
cd local-translator

python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install -r requirements.txt
playwright install chromium
```

Сборка интерфейса (Windows):

```powershell
.\build.ps1          # получится translator-ui.exe
```

Вручную, на любой ОС:

```sh
cd frontend && npm install && npm run build && cd ..
go -C backend build -o ../translator-ui .
```

## Использование

### Через интерфейс

```sh
./translator-ui            # откроет http://127.0.0.1:8765 в браузере
```

Флаги: `-root <папка>` указывает папку проекта с `config.yaml`, `-addr 127.0.0.1:8765` задаёт адрес,
`-no-open` запускает сервер без браузера.

Перетащите PDF в окно или положите его в `in/`. Готовые переводы появляются в `out/`.

### Через командную строку

```sh
python -m src.cli run                     # перевести все PDF из in/
python -m src.cli run book.pdf --mode quality
python -m src.cli resume                  # продолжить прерванное
python -m src.cli status                  # состояние очереди
python -m src.cli preview book.pdf        # разобрать и собрать PDF без перевода, чтобы проверить вёрстку
python -m src.cli rerender                # пересобрать PDF после правки шрифтов или CSS
python -m src.cli import-glossary terms.xlsx --group my-series
```

Остальные команды выводит `python -m src.cli --help`.

## Настройка

Все параметры лежат в [`config.yaml`](config.yaml), у каждого есть комментарий. Чаще всего меняют:

- `source_lang` / `target_lang`: языки перевода;
- `llm.modes`: режимы и модели для первого и второго прохода;
- `llm.prompt_ver`: увеличьте после правки промпта, и затронутые куски переведутся заново;
- `render`: шрифт, кегль, поля и размер страницы (`auto` означает размер оригинала).

### Глоссарий

`glossary.tsv` хранит пары «термин, табуляция, перевод», по одной на строку. Строки, начинающиеся с `#`, считаются
комментариями. Пример лежит в [`glossary.example.tsv`](glossary.example.tsv). Свои глоссарии, подсказки,
список персонажей и группы книг не попадают в git: это личные данные, они указаны в `.gitignore`.

## Разработка

```sh
pytest                        # тесты конвейера: без Ollama и браузера, на синтетических PDF
go -C backend test ./...      # тесты сервера

cd frontend && npm run dev    # интерфейс с горячей перезагрузкой; сервер на Go должен быть запущен
```

Структура проекта:

```
src/          конвейер: extract, chunk, llm, validate, characters, names, render, cli
backend/      HTTP-сервер и API интерфейса (собранный фронтенд в backend/dist встраивается через go:embed)
frontend/     React-интерфейс
tests/        тесты конвейера
config.yaml   настройки
in/ out/ work/  входные PDF, результаты, промежуточные файлы (создаются автоматически)
```

## Авторские права

Переводите только те книги, на которые у вас есть права. Не публикуйте переводы чужих произведений
без разрешения правообладателя. В репозитории нет ни одной книги.
